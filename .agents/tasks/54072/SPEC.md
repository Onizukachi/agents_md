# LT-54072 — Академия Сервиса переходит на ОСН без лицензии

## Problem

Система налогообложения, которая печатается в чеке и уезжает в ОФД, вычисляется из флага
«Лицензия в чеках» (`organizations.has_license`): есть лицензия — ОСН, нет — УСН «доход минус расход».
Этот же флаг одновременно управляет тремя другими вещами: печатью лицензионной позиции в чеке
детализации, начислением НДС на допы и наличием сервисного сбора в заказе.

С 14.09.2026 Организация «Академия Сервиса» (id 7) переходит на ОСН, **оставаясь без лицензии**.
Разделить эти два факта сейчас нечем: переключение флага изменит режим налогообложения, но заодно
включит лицензионную позицию, выключит НДС по допам и уберёт сервисный сбор, а не переключать его
нельзя — иначе в чеках останется УСН.

Три связанные проблемы, которые всплыли при разборе:

- Режим налогообложения в PDF читается из текущей настройки Организации, а не из того, что реально
  пробито. После переключения все 132 854 ранее выданных чека Академии при повторной печати или
  отправке письма покажут ОСН, хотя пробиты с УСН.
- Ставка НДС по допу берётся на дату создания заказа. По заказам, созданным до 01.07.2026, чеки
  до сих пор пробиваются со ставкой 5% — это ставка УСН, на ОСН её не существует. В сентябре так
  прошли 42 позиции из 260.
- Строка «СУММА НДС» в PDF считается начислением сверху цены (`цена × ставка / 100`), тогда как цена
  в чеке включает НДС и налог надо извлекать расчётной ставкой. На ставке 22% расхождение с
  фискальным документом составляет пятую часть суммы налога: за 01.08–11.09.2026 налог завышен
  на 29 434 ₽ (160 342,60 ₽ вместо 131 427,48 ₽ по ставке 22% и 10 895,95 ₽ вместо 10 376,97 ₽ по 5%).

## Solution

Режим налогообложения перестаёт быть производной от лицензии и становится собственной настройкой
Организации с периодами действия — по образцу уже существующего реестра ставок НДС у Operator
Organization. Для Академии заводятся две записи: УСН «доход минус расход» по 13.09.2026 и ОСН
с 14.09.2026. Остальным Организациям записи не нужны: значение по умолчанию — ОСН, что совпадает
с их фактическим режимом за всю историю.

Режим для конкретного чека определяется на дату этого чека, а не «по текущей настройке», поэтому
ранее выданные чеки продолжают печататься с тем режимом, с которым были пробиты. Дополнительной
страховкой служит фактически пробитое значение, сохранённое в данных чека: если оно есть, PDF
показывает именно его.

Ставка НДС по допу тоже начинает определяться на дату чека, а не на дату создания заказа, — так
хвост старых заказов добивается ставкой 22% и не порождает сочетания «ОСН + 5%».

Расчёт строки «СУММА НДС» переводится на расчётную ставку с построчным округлением — так же, как
считает кассовый аппарат. Перевыпускать чеки не нужно: PDF формируется на лету, поэтому все ранее
выданные чеки начинают печататься корректно сами.

Флаг «Лицензия в чеках» у Академии остаётся выключенным, поэтому лицензионная позиция, правило
начисления НДС на допы и сервисный сбор не меняются ни у Академии, ни у остальных Организаций.

## Scenarios

1. Чек Академии, созданный до 14.09.2026, — и в ОФД, и в PDF режим «УСН доход - расход».
2. Чек Академии, созданный 14.09.2026 или позже, — режим «ОСН».
3. Чек Организации без записей в реестре (ЛТ, ЛП, прочие) в любую дату — режим «ОСН».
4. Ранее пробитый чек Академии, PDF которого формируется повторно после перехода, — показывает
   «УСН доход - расход», то есть фактически пробитый режим.
5. Позиция допа в чеке детализации Академии, поставщик которого — Академия Сервиса: НДС по ставке,
   действующей на дату чека (22% для чеков с 01.07.2026).
6. Та же позиция по заказу, созданному до 01.07.2026, чек по которому пробивается после релиза:
   НДС 22%, а не 5%.
7. Позиция допа с поставщиком, у которого нет действующей ставки (Ренессанс Страхование,
   Transferiya и прочие): «НДС не облагается».
8. Любая позиция в чеке Организации с лицензией (ЛТ, ЛП): «НДС не облагается».
9. Позиция тура в любом чеке: «НДС не облагается» — правило не меняется.
10. Авансовый чек любой Организации: одна позиция, без НДС, режим налогообложения — по дате чека.
11. Строка «СУММА НДС N%» равна сумме налога, извлечённого из цен позиций расчётной ставкой
    `цена × ставка / (100 + ставка)`, с округлением до копейки по каждой позиции.
12. Чек с позициями по разным ставкам: несколько строк «СУММА НДС», по строке на ставку,
    отсортированных по возрастанию ставки.
13. Позиция с расчётным кодом ставки (105, 107, 110, 120, 122): подпись показывает соответствующий
    процент (5, 7, 10, 20, 22), сумма налога считается тем же извлечением.
14. Чек без позиций с НДС: печатается «НДС НЕ ОБЛАГАЕТСЯ».
15. Чек возврата по детализации: те же правила режима и ставки, что и для прихода, по дате
    чека возврата.

## Implementation decisions

**Реестр систем налогообложения.** Новая таблица с внешним ключом на Организацию, значением режима
и периодом действия (дата начала обязательна, дата окончания пустая означает «бессрочно»), новая
модель с проверкой попадания даты в период и валидацией периода. Пара «режим + период» редактируется
в карточке Организации вложенными атрибутами; предыдущий открытый период автоматически закрывается
днём раньше начала следующего, пересечения периодов запрещены валидацией. Всё это зеркалит реестр
ставок НДС у Operator Organization, вплоть до формы в админке; существующий концерн ставок НДС
не трогаем и не обобщаем.

**Чтение режима.** Организация отвечает на вопрос «какой режим действовал на дату X»; при отсутствии
записи возвращает ОСН. Методы Организации, выводящие режим из лицензии, удаляются вместе с
неиспользуемым предикатом «общий режим».

**Режим конкретного чека.** Чек сам определяет свой режим: если в его фискальных данных сохранён
фактически пробитый код режима — используется он (код разворачивается в режим через справочник
соответствующего фискализатора), иначе — режим Организации на дату создания чека. Первая ветка
работает для уже пробитых чеков, вторая — для чека, который только формируется. Делегат режима
на Организацию убирается.

**Ставка НДС.** Правило «НДС только на позициях допов и только у Организации без лицензии»
не меняется; меняется дата, на которую ищется ставка поставщика: вместо даты создания заказа —
дата создания чека. Правка симметрично вносится в оба фискализатора.

**Расчёт суммы НДС.** Вычисление выносится из модуля отрисовки PDF в отдельный небольшой сервис,
который принимает позиции чека и возвращает готовые пары «подпись — сумма»; модуль PDF только
рисует то, что сервис вернул. Сервис извлекает налог расчётной ставкой, округляет по каждой позиции
до копейки и суммирует по ставке, а расчётные коды ставок приводит к соответствующему проценту
и для подписи, и для расчёта.

**Парсер фискальных данных.** Путь до кода режима налогообложения исправляется на верхний уровень
ответа, чтобы фактически пробитый режим сохранялся в разобранных данных чека.

**Данные.** Разовая rake-задача в `one_time` заводит Академии две записи реестра: УСН «доход минус
расход» по 13.09.2026 включительно и ОСН с 14.09.2026 бессрочно. Задача идемпотентна — повторный
запуск не создаёт дублей.

**Схема.** Одна новая таблица; существующие не меняются. Миграция выполняется по правилам проекта:
`safety_assured`, гарды существования, применение и проверка схемы внутри контейнера.

## Testing decisions

Тестируем внешнее поведение на трёх швах, минимальным набором примеров.

1. **Организация: режим на дату.** Две записи реестра с периодами — даты внутри первого периода,
   внутри второго и до начала первого; Организация без записей отвечает ОСН. Прообраз —
   `#vat_on` в `spec/models/operator_organization_spec.rb:70`. Существующая
   `spec/models/organization_spec.rb` проверяет связку режима с лицензией и переписывается
   под новое поведение.
2. **Что уезжает в ОФД.** Самый высокий доступный шов без похода в сеть — формирование данных
   запроса фискализатора Uniteller: чек Академии до и после даты перехода даёт разные коды режима,
   а позиция допа Академии по заказу, созданному до 01.07.2026, но пробиваемому после релиза,
   получает ставку 22%. Прообраз по фабрикам и обвязке — `spec/apis/fiscal_router/fiscal_router_spec.rb`.
3. **Расчёт суммы НДС.** Сервис расчёта: извлечение налога из цены (позиция 949 ₽ по ставке 22%
   даёт 171,13 ₽), несколько ставок в одном чеке, расчётный код ставки, отсутствие позиций с НДС.

Не тестируем: рендер PDF целиком, форму админки, rake-задачу, путь CheckOnline.

## Out of scope

- Флаг «Лицензия в чеках» и всё, что на нём висит: лицензионная позиция в чеке детализации,
  сервисный сбор, само правило «НДС начисляем только у Организации без лицензии», гарды детализации.
- НДС на позиции тура и в авансовых чеках — правила не меняются.
- Ставки НДС других Operator Organization и содержимое реестра ставок.
- Возврат по ставке исходной продажи: возвратов по собственным допам Академии нет ни одного,
  отдельное правило не вводится.
- Фискализатор CheckOnline: правка даты ставки вносится симметрично, но не проверяется — последний
  чек через него пробит 11.08.2025.
- Контракты и документация PAPI v3 — не затрагиваются.
- Перевыпуск и правка данных ранее выданных чеков.
