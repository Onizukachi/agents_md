# LT-54786 — прогресс реализации

Спецификации нет: решение согласовано в разговоре 14.10.2026.

## 14.10.2026

### Контекст (проверено на проде)
- Турвизор присылает «Турплатформа»; у нас TourPlatform (id 100) отключён, и по названию он не находится даже без фильтра по `enabled`. С 01.08.2026 94 заказа ушли на Level.Travel (78).
- Последствия ТО 78 на таких заказах:
  - FastConfirm (все заказы на `DYNAMIC_IDS` без фильтра по партнёру) перезаписывает `operator_order_url` на `dynamic.lvtv.me/admin/bookings/<id>` и ежечасно пишет ошибки синка в лог заказа;
  - договор и чеки уходят с юрлицом ООО «ГорТревел»;
  - к заказу прикладывается PDF Dynamic про страховку.
- Для ТО 100 данные уже есть: активное основное юрлицо (operator_organizations.id 100) и статья `agreement_operator_info_100`.
- Синк Турвизора для отельных заказов на 78 (LT-53981) не работает: с 11.10 по 16 заказам все 95 попыток падают с `supplier-orders request failed: internal_error`.

### Согласованные правила подбора ТО (`PartnerHooksHandlers::PackageBuilder#matched_operator`)
1. Ключ поиска — как раньше: значение из `OPERATOR_NAMES`, иначе первое слово названия.
2. Ищем подстроку среди всех ТО. Если есть совпадения среди включённых, берём только их, иначе — отключённые.
3. Кандидатов больше одного → Level.Travel (правило одинаково для включённых и отключённых).
4. Единственный отключённый ТО без активного основного юрлица → Level.Travel. Без юрлица ломаются проведение платежа, чеки и показ ТО в менеджерке.
5. Причина подстановки Level.Travel пишется в комментарий заказа: не найден / найдено несколько (с перечнем) / отключён без юрлица.

### Сделано
- Ветка `feature/LT-54786-tourvisor-disabled-operators` от свежего `develop`.
- `package_builder.rb`: `matched_operator` разделён на `operator_candidates` и `operator_candidates_error`. Поиск через параметр и `sanitize_sql_like` вместо подстановки строки в SQL.
- `tourvisor/order_creator.rb`, `OPERATOR_NAMES`:
  - добавлены `Турплатформа → TourPlatform`, `Xpress Travel → Xpress Travel` (раньше попадал в Russian Express), `PAC GROUP → Pac Group` (раньше попадал в Space Travel), `Амиго-С → Amigo-s`, `Арт-Тур → АРТ ТУР`;
  - `"Let''s Fly"` → `"Let's Fly"`: двойная кавычка была нужна только для ручной вставки в SQL.
- Спеки `spec/services/partner_hooks_handlers/tourvisor/order_creator_spec.rb`, `#matched_operator`:
  - убраны заглушки `Operator.only_enabled` у двух старых контекстов;
  - 7 новых контекстов на реальных записях: включённый важнее отключённого дубля, кавычка в названии, Xpress Travel, несколько включённых, отключённый с основным юрлицом (Турплатформа), отключённый без основного юрлица, несколько отключённых.
- Прогон: `spec/services/partner_hooks_handlers/`, `spec/workers/tourvisor_order_sync_worker_spec.rb`, `spec/workers/tourvisor_order_sync_work_generator_spec.rb` — 65 examples, 0 failures (после разнесения проверок fallback и комментария по отдельным `it` по rspec-style-guide — 68). Перед прогоном пересоздана тестовая БД: в ней не было `place_flags` из develop.

### Вне задачи (решено с пользователем)
- Уже созданные заказы Турплатформы на 78 не переносим: по ним выбиты чеки и созданы ОП на юрлицо ГорТревел.
- Синк Турвизора (supplier-orders) для ТО 100 не добавляем. При необходимости — отдельная задача с Go-стороной.
- Ручное создание заказа в менеджерке не меняется.
- Online Express остаётся на Level.Travel: по ключу `ONLINE` подходят два отключённых ТО. Сопоставление добавим, если бизнес подтвердит, что это Russian Express.
- Поиск по целому слову вместо подстроки (чтобы `PAC`/`ONE` не совпадали с чужими ТО) предлагался, но не выбран.
