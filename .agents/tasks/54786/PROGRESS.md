# LT-54786 — прогресс реализации

Спецификации нет: решение согласовано в разговоре 14.10.2026.

## 14.10.2026

### Контекст (проверено на проде)
- Турвизор присылает «Турплатформа»; у нас TourPlatform (id 100) отключён, и по названию он не находится даже без фильтра по `enabled`. С 01.08.2026 94 заказа ушли на Level.Travel (78).
- Последствия ТО 78 на таких заказах:
  - FastConfirm (все заказы на `DYNAMIC_IDS` без фильтра по партнёру) перезаписывает `operator_order_url` на `dynamic.lvtv.me/admin/bookings/<id>` и ежечасно пишет ошибки синка в лог заказа;
  - договор и чеки уходят с юрлицом ООО «ГорТревел»;
  - к заказу прикладывается PDF Dynamic про страховку.
- Для ТО 100 данные уже есть: активное основное юрлицо (operator_organizations.id 100) и статья `agreement_operator_info_100`.
- Синк Турвизора для отельных заказов на 78 (LT-53981) не работает: с 11.10 по 16 заказам все 95 попыток падают с `supplier-orders request failed: internal_error`.

### Согласованные правила подбора ТО (`PartnerHooksHandlers::PackageBuilder#matched_operator`)
1. Ключ поиска — как раньше: значение из `OPERATOR_NAMES`, иначе первое слово названия.
2. Ищем подстроку среди всех ТО. Если есть совпадения среди включённых, берём только их, иначе — отключённые.
3. Кандидатов больше одного → Level.Travel (правило одинаково для включённых и отключённых).
4. Единственный отключённый ТО без активного основного юрлица → Level.Travel. Без юрлица ломаются проведение платежа, чеки и показ ТО в менеджерке.
5. Причина подстановки Level.Travel пишется в комментарий заказа: не найден / найдено несколько (с перечнем) / отключён без юрлица.

## 16.10.2026 — служебный ТО и пропуск чеков

### Решения бизнеса и пользователя
- Сопоставления: `Online Express → Russian Express Online` (73, основное юрлицо «Э-Холидейз»), `OneTouch & Travel → One Touch Travel` (82, «Вантач Трэвел»).
- Не найден / найдено несколько / у найденного ТО нет активного основного юрлица → заказ ставится на «Служебного» ТО вместо Level.Travel (78). В комментарий заказа: причина + «найдите настоящего ТО и смените его в заказе».
- Проверка юрлица теперь для всех ТО, не только отключённых (на проде у всех 18 включённых основное юрлицо есть, поведение не меняется). По решению пользователя живёт только в Турвизоре: `Tourvisor::OrderCreator#operator_candidates_error` (через `super`); в общем `PackageBuilder` остались «не найден» и «найдено несколько».
- По заказу на служебном ТО чеки не выбиваются: аванс и возврат пропускаются с записью в логе заказа (`fiscals`), детализация ставит заказ на ручной разбор (`ReceiptDetailingBlock` с причиной `service_operator`, если есть деньги). Решение по возврату — по текущему ТО заказа, без флага на платеже: флаг пользователю не понравился, а возврат без аванса после смены ТО Uniteller всё равно отклонит (пользователь). Отвергнуты: флаг в `payment.data`; «нет чека аванса у платежа Турвизора» (задело бы 1957229/1960665 — платежи 10–12.10 без чеков).

### Почему так (проверено по коду и проду)
- ТО без активного юрлица → `packages.operator_organization_id = NULL` → падают: авансовый чек в хуке оплаты (`LineItemsV2::Advanced::Creator.tour_supplier_id`), списание (`Payment#correct_split_value`, `#set_operator_organization`), доплаты (`PaymentBuilder`), детализация; `ReceiptFiscalizer`/`OrderStatusChecker` обрываются на таком заказе. Хук оплаты приходит через 1–10 минут после заказа (96% из 597 с 07.2026), вручную завести юрлицо не успеть. Заказов без юрлица на проде не было с 20.08.2024.
- Поэтому у служебного ТО есть фиктивное активное основное юрлицо без ИНН и телефона: без него ломаются списание, доплаты и список операторов в менеджерке (INNER JOIN по юрлицам).
- Пропуск только фискализации отвергнут: снимок поставщика первого аванса навсегда закрепил бы служебного ТО, а `fiscalization_skipped` считается завершённым чеком, и детализация переносила бы аванс, которого нет в Uniteller.
- Поставщик аванса (`Snapshot`) на служебном ТО не фиксируется, после смены ТО первая доплата закрепит настоящего; детализация без пропущенного аванса уходит в `amount_mismatch` (ручной разбор).

### Учесть
- Заказы на служебном ТО не подхватывает синк Турвизора (`HOTEL_ONLY_OPERATOR_IDS = [78]`).
- Описание PR #27158 переписать: fallback теперь служебный ТО, а не 78.
